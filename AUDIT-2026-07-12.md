## NEW — CONFIG / DEPLOYMENT

### N1 (HIGH) — SSO route is gitignored; the security fixes are not in version control
`.gitignore` excludes `web/app/api/auth/` (and `wordpress/`). Git history shows the route was committed once (`ca24473`) then untracked (`5de8c06`). Consequences:
- The **only version in git history is the OLD, vulnerable one** (pre-C3/pre-H1). The secured route (org-binding at `route.ts:121`, replay table insert at `:60`) exists **only on local disk, untracked**.
- CLAUDE.md states the frontend "auto-deploys on push to main." If Vercel builds from GitHub, the deployed build either has **no `/api/auth/sso` endpoint at all** (file removed from repo) or a stale one. There is no `web/.vercelignore`, so a local `vercel` CLI deploy also honors `.gitignore` and would omit the route too.
- A fresh clone loses the fixes silently.

The route contains **no secrets** (all secrets are env vars), so there is no reason to ignore it. **Action:** confirm what production actually serves for `/api/auth/sso`; then un-ignore `web/app/api/auth/` and `wordpress/`, commit the current secured versions, and redeploy. This is the highest-leverage item in this pass — the July-10 SSO work may not be live.

### N2 (MEDIUM) — SSO one-time token is consumed *before* login can succeed (reliability regression from H1)
`web/app/api/auth/sso/route.ts:60-70`. The replay-protection row is inserted right after the signature/expiry checks — but **before** org resolution, user creation, `generateLink`, and `verifyOtp`. If any later step fails transiently (Supabase blip, org lookup miss), the token is already committed, so the user's still-valid link returns `Link already used` on retry and they can never log in. Security is fine; availability is not. **Fix:** insert the token only after the session is successfully created, or delete it on every failure path after the insert.

### N3 (LOW) — SSRF guard has a DNS-rebinding TOCTOU
`web/app/api/news/route.ts` — `assertPublicUrl()` resolves the host, then `fetch()` resolves it again independently. Attacker-controlled DNS can answer public on the check and private on the fetch. Admin-gated, so low severity, but the guard isn't airtight. **Fix:** resolve once, pin the validated IP for the actual connection (or use an agent that re-checks the connected socket address).
