# StallionTracker Audit — 2026-07-10

Read-only audit of database, web API, frontend, and Python services. Nothing was modified. The four CRITICAL/HIGH-priority items below were verified directly against source; the rest come from four parallel subagent reviews.

## Verdict
The app is well-architected in shape (RLS-first reads, currency-aware Europe pipeline, careful auth lifecycle, strict TS passing), but has **two critical database RLS holes that allow full multi-tenant compromise with only an anon key**, plus a **cross-tenant SSO account-takeover**. Fix those three before anything else.

---

## CRITICAL

### C1 — Any user can self-promote to admin / switch orgs (verified)
`database/migrations/001_auth_and_rls.sql:84-85`
```sql
CREATE POLICY "users_update_self" ON users
  FOR UPDATE USING (auth_id = auth.uid());
```
No `WITH CHECK`, no column restriction. `role` and `organization_id` are freely writable via PostgREST with the anon key: `UPDATE users SET role='admin'` or `SET organization_id='<other org>'`. Because `is_admin()` / `get_user_organization_id()` read this same user-writable table, this defeats every policy in the system.
**Fix:** `WITH CHECK (auth_id = auth.uid() AND role = 'user')` and block org changes (trigger or service-role-only writes to those columns).

### C2 — "service_*" RLS policies apply to PUBLIC, not the service role (verified)
`001_auth_and_rls.sql:131,135,151,154,170,173,189,192,206,220,234`; `003:199,204`; `009:26`. None carry a `TO service_role` clause, so `FOR ALL USING (true)` / `WITH CHECK (true)` grant **every anon/authenticated caller** insert/update/select/delete on `horses`, `entries`, `results`, `workouts`, `sales_stats`, `sire_rankings`, `equineline_stats`, `stallion_fee_history`. The service role bypasses RLS anyway and never needed these.
**Fix:** drop all these policies (simplest), or add `TO service_role`.

### C3 (web) — SSO mints a session for any existing email regardless of signing org (verified)
`web/app/api/auth/sso/route.ts:78-115`. The HMAC is verified against the per-org secret for the `org` param, but when the email already has an account the code selects only `id` and **skips re-validating `organization_id`**. Any partner holding one valid `SSO_SECRET_<ORG>` can sign `victim@otherorg.com|theirOrg|exp` and log in as that other org's user (incl. an admin).
**Fix:** after resolving `existingProfile`, reject unless `existingProfile.organization_id === organization.id`.

## HIGH

- **H1 (web) — SSO replay:** `auth/sso/route.ts` checks `exp` but has no nonce/single-use. Signed URLs (in history, Referer, logs) are replayable until expiry. Add a one-time `jti`.
- **H2 (db) — Tables with no RLS at all:** `chart_data`, `email_log`, `digest_log` (schema.sql:242-304) — readable/writable via anon key. `digest_log.recipient_emails` leaks subscriber PII.
- **H3 (db) — Legacy views bypass RLS:** `todays_entries`, `recent_results`, `recent_workouts` (schema.sql:336-381) lack `security_invoker`; auto-exposed by PostgREST → cross-org leak. (`stallion_ytd_stats` correctly sets it.)
- **H4 (db) — SECURITY DEFINER funcs lack `SET search_path`:** the four RLS helpers (001, 015).
- **H5 (db) — Migration drift:** migration 002 missing; 001 references `equineline_stats` created in 003 (dir won't apply in order); `users.show_claiming_races` / `organizations.allow_claiming_toggle` exist in code but no SQL file; schema.sql can't rebuild prod (references `race_country` before 010 adds it, `stud_fee INTEGER` vs 005's TEXT). No migration ledger.
- **H6 (py) — Digest Jinja2 autoescape OFF:** `digest/generate_digest.py:34`. Scraped news titles + email-derived horse/owner names inject raw HTML into client emails. One-line fix: `autoescape=True`.
- **H7 (py) — IMAP fetches mail from ANY sender:** `gmail_client.py:69` `OR ... SUBJECT "Notification"` lets any email with "Notification" in the subject enter the parse pipeline → DB poisoning + injected strings.
- **H8 (py) — Unanchored Equibase URL regexes:** `result_parser.py:144,155`, `entry_parser.py:276`, `workout_parser.py:49` substring-match `equibase.com/...`; a crafted email can point the fetcher at an arbitrary host (SSRF, attacker PDF into pdfplumber, link-hijack in emails). Validate hostname.
- **H9 (py) — Digest crashes on DNF results:** `generate_digest.py:163,499` — `finish_position=None` (European PU/FF) raises `TypeError` in sort and `n%100` ordinal; the whole daily send dies.
- **H10 (web) — Self-imposed fetch timeouts wedge the UI:** `app/page.tsx:112-148` and `app/dashboard/page.tsx:74-105` — on timeout the abort is treated as unmount, `loading` stays `true` forever with no error/retry. Dashboard shares one controller across 3 fetches, discarding successful responses.

## MEDIUM (selected)

- **Server auth uses `getSession()` not `getUser()`** everywhere (`lib/api-auth.ts:35`, `middleware.ts:44`, all admin routes) — reads cookie without revalidating JWT. `app/layout.tsx:47` already uses `getUser()`; be consistent.
- **SSRF in news OG fetcher:** `web/app/api/news/route.ts:116-139` fetches admin-supplied URLs, follows redirects, no private-IP block (admin-gated → lower severity).
- **`/api/bookings` leaks all orgs' branding** to any authed user (service-role query, no filter) — `bookings/route.ts:7-21`.
- **XSS in PDF export:** `web/lib/pdf-export.ts` interpolates unescaped horse/owner/race names + URLs into `innerHTML`. Only injection sink in the app (React handles the rest safely).
- **`auth-context.tsx:306` dead SSR optimization:** compares `users.id` (PK) to auth uid — never equal, re-fetches profile every mount.
- **Currency loses its label in scraper/sales paths:** TDN sire/sales money stripped of £/€/gns and stored/rendered as `$` (`tdn_sire_list_scraper.py:156`, `components/SalesCard.tsx`, digest templates hardcode `$` on `purse_currency`-bearing rows). Arion/PMU path does this correctly.
- **YTD view currency proxy is fragile:** `012` filters `race_country IS NULL` as a USD proxy, but Arion emits `'USA'`; should use `earnings_currency`.
- **`results.purse` means two different things** (horse earnings on US path, race purse on Arion) — data-model landmine.
- **Failed emails never retried:** `db.is_email_processed` ignores the `success` flag → transient failures = permanent silent data loss.
- **`?tab=history` deep link broken** (`app/page.tsx:79` missing from valid list).
- **requirements.txt floor-pinned (`>=`)** in an unattended pipeline holding the service key.

## LOW (selected)
Incomplete track-timezone table (defaults ET, mislabels West Coast/Central); machine-local `date.today()` in digest flips "yesterday" on UTC runners; digest recipients all in one `to:` field (leaks client list); missing FK indexes; `digest_log` no unique(stallion_id,date); dead code (`StallionBookingsCard`, `updateProfile`, `build_replay_url_simple`); ESLint not installed so `exhaustive-deps` never runs; offset pagination drift in news; weak SSO user-list pagination (unpaginated `listUsers()`).

## Strengths
RLS *shape* is correct where not undermined; `stallion_ytd_stats` uses `security_invoker`; news schema dedup + partial unique indexes are well done; ingestion dedup constraints solid; SSO HMAC compare is timing-safe; middleware correctly excludes `/api` and every route self-authenticates; strict TS passes clean; jsPDF/html2canvas dynamically imported; `lib/currency.ts` + `lib/timezones.ts` are proper single sources of truth; parser canonicalization + "never weaken existing data" upsert guards + news false-positive rigor are genuinely strong; secrets are env-only and `.env` files were never committed (git history clean).

## Remediation applied (2026-07-10)
Security fixes committed to the working tree. TypeScript `tsc --noEmit` passes; Python syntax + new helpers unit-checked.

**Database — `database/migrations/019_security_hardening.sql` (new; apply in Supabase SQL Editor):**
- C1: BEFORE UPDATE trigger `prevent_user_privilege_escalation` blocks non-admins from changing their own `role`/`organization_id`; service role and admins bypass. Self-update policy given an explicit `WITH CHECK`.
- C2: dropped all 12 `USING(true)` `service_*` policies + the 003 public-read policy (service role bypasses RLS, so no behavior change for the parser).
- H2: enabled RLS on `chart_data`, `email_log`, `digest_log` (no anon/authenticated policies → parser-only via service role).
- H3: `security_invoker = true` on `todays_entries`, `recent_results`, `recent_workouts`.
- H4: pinned `search_path` on the 4 SECURITY DEFINER helper functions.
- H1(web): added `sso_used_tokens` table for SSO replay protection.

**Web:**
- C3: SSO route now rejects when an existing account's `organization_id` ≠ the signing org (`auth/sso/route.ts`).
- H1: SSO records each signature in `sso_used_tokens`; replay → 401.
- M1: all server auth switched `getSession()` → `getUser()` (middleware, `api-auth.ts`, 4 `verifyAdmin` helpers, admin/users).
- M2: news OG fetcher now resolves DNS and blocks private/reserved IPs, follows redirects manually re-validating each hop (`api/news/route.ts`).
- L1: `/api/bookings` themes scoped to the caller's visible orgs (admins still see all).
- XSS: `lib/pdf-export.ts` escapes all data leaves (names, URLs, connections, silks `src`) before `innerHTML`.

**Python:**
- H6: digest Jinja2 `autoescape=True` (verified escapes `<img onerror>`).
- H8: new `parsers/equibase_urls.py` validates link *host* is equibase.com; 5 substring-regex matchers in result/entry/workout parsers replaced (verified against spoofed-host URLs).

**Deferred by decision:** H7 — IMAP fetch (`gmail_client.py:69`) accepts any sender with "Notification" in the subject. Left as-is at owner's request (2026-07-10); the URL-anchoring (H8) and autoescape (H6) fixes neutralize the SSRF and email-HTML-injection consequences, leaving only fake-data-poisoning as residual risk. Revisit if forwarding setup is confirmed.

**Not addressed (correctness bugs, not security):** H9 digest DNF crash, H10 frontend timeout-wedge, M-tier currency labeling. Available to fix on request.

## Recommended fix order
1. C1 — `WITH CHECK` on `users_update_self`
2. C2 — drop/scope all `USING (true)` policies
3. C3 + H1 — SSO org-binding + replay nonce
4. H2/H3 — RLS on `chart_data`/`email_log`/`digest_log`; `security_invoker` on legacy views
5. H6 — digest `autoescape=True`
6. H7/H8 — restrict IMAP sender + anchor Equibase URLs
7. H9/H10 — DNF-safe digest; fix timeout-wedge
